# 浏览器执行器规范（browser-policy）

> 适用：P4 阶段及之后，任何需要通过浏览器读取或操作招聘页面的动作。
> 定版：2026-10-29 ｜ 对应 `config/settings.json` 的 `browser_exec` 能力项。
> **本文件规定「怎么用」，不规定「能不能用」**；能不能用只由 `doctor` 的实测证据决定。

## 0. 总原则（三条，冲突时按序）

1. **优先用宿主内置能力，不自建浏览器栈。** WorkBuddy 已提供浏览器控制（`mcp__browser__*` 工具族）与 `workbuddy-browser-use` Skill。禁止另行安装 Selenium / Playwright / Puppeteer / puppeteer-core 等，理由：新增依赖会破坏「零第三方依赖」承诺（`THIRD_PARTY_NOTICES.md`），且需要下载浏览器驱动，与本项目「本地、轻量、可移植」定位冲突。
2. **复用用户已登录的标签页，不由我们完成登录。** 这是本规范的核心设计，详见第 1 节。
3. **只读优先，读写分离，提交动作与填写动作分开确认。** 详见第 3、4 节。

## 1. 标签页获取优先级（安全等级从高到低）

| 优先级 | 做法 | 用到什么 | 为什么 |
| --- | --- | --- | --- |
| **A（首选）** | 让用户自己打开并登录目标页面，用 `user_open_tabs` 列出后 `tabs_claim` 接管该标签页 | `mcp__browser__user_open_tabs` → `tabs_claim` | 登录由用户完成，本 Skill **完全不接触账号密码、Cookie、令牌**；用户在屏幕上全程可见操作，不存在后台静默行为 |
| **B（仅只读）** | 我们 `tabs_new` + `tab_goto` 打开**公开可访问**的岗位页 | `tabs_new` / `tab_goto` | 只读抓取公开页面时不必打扰用户；一旦出现登录墙立即停止 |
| **C（禁止）** | 由本 Skill 填账号密码、点登录、走短信/扫码登录 | — | 违反 `security-policy.md`：不代为保管、不代为填写任何登录凭据 |

**A 的执行序列（标准写法）**

```
1. browser_info / browsers_list      → 确认连的是哪个浏览器实例
2. user_open_tabs                    → 列出用户已开标签页，向用户复述标题与 URL
3. 用户指认目标标签                 → 不得自行猜测「大概是这一个」
4. tabs_claim                        → 只接管这一个标签页
5. tab_url / tab_title               → 复核确认接管对象正确
6. dom_cua_get_visible_dom           → 读结构（只读）
```

> 接管前必须向用户复述「我要操作的是：<标签标题> — <URL>」，得到确认才 `tabs_claim`。
> 接管期间不得关闭用户的其他标签页；结束时用 `tabs_finalize` 释放，**不关闭用户的标签页**。

## 2. 操作方式优先级：DOM 优先于坐标

| 优先级 | 工具族 | 稳定性 | 何时用 |
| --- | --- | --- | --- |
| 1 | `dom_cua_get_visible_dom`（读）<br>`dom_cua_click` / `dom_cua_type` / `dom_cua_keypress` / `dom_cua_scroll`（写） | 高：按元素定位，不受分辨率、缩放、滚动位置影响 | 默认首选 |
| 2 | `tab_screenshot`（读）<br>`cua_click` / `cua_double_click` / `cua_type` / `cua_keypress` / `cua_scroll` / `cua_drag`（写） | 低：按截图像素坐标，缩放/DPI/窗口大小一变就漂移 | 仅当 DOM 拿不到目标元素（canvas 渲染、跨域 iframe、极度动态页面） |
| — | `cua_execute` | 取决于所执行的脚本 | 仅在上述都不够时，且需先向用户说明将执行什么 |

**硬性规则**

- 用坐标点击（`cua_*`）前，必须先 `tab_screenshot` 重新截图，坐标基于**本次**截图；不得复用缓存坐标。
- 任何一次坐标点击后，必须再截图或读 DOM 复核结果，不得连续盲点。
- 滚动后坐标全部失效，必须重新截图。

## 3. 只读 / 写入分层

| 层级 | 动作 | 是否需要确认 |
| --- | --- | --- |
| L0 只读 | `tab_url`、`tab_title`、`tab_screenshot`、`dom_cua_get_visible_dom`、`tab_reload` | 不需要（但截图落盘位置受第 6 节约束） |
| L1 导航 | `tabs_new`、`tab_goto`、`tab_back`、`tab_forward` | 需要：说明目标 URL 与用途 |
| L2 填写 | `dom_cua_type`、`dom_cua_click`（非提交类元素，如展开详情、切换 tab）、`cua_type`、`cua_click` | 需要：**逐字段说明要填什么值、值来自档案哪条 `confirmed` 事实** |
| L3 提交 | 点击任何 `submit` / `立即申请` / `确认投递` / `发送` / `支付` 类元素 | 需要**独立的一次显式确认**，且不得与 L2 合并在同一轮 |

**L3 的强制约束**

1. 提交按钮的点击**默认由用户自己完成**（`run_mode = semi_auto`）。我们填完、截图、把「还差最后一步：点这个按钮」告诉用户，然后停。
2. 用户明确说「这一条你帮我点提交」时，才允许执行 L3，且必须：先 `tab_screenshot` 留证 → 点一次 → 立即再截图或读 DOM 抓确认结果 → **立刻**把可见的申请编号/确认页文本登记为 `submission_evidence`。
3. 只允许点**一次**。点击后无论结果如何，都不得再次点击（防重复投递）。若无任何可验证的确认结果，状态**不得**标记 `已提交`，只能记为 `需人工介入`。
4. 一个岗位一个确认，禁止「这批都确认了，一起点」。

## 4. 必须立即停止的情形

出现任一项，立即停止本次浏览器操作，转为 `需人工介入`，并在报告中写明触发原因与当前 URL：

| 停止条件 | 判定方式 |
| --- | --- |
| 出现验证码 / 人机验证 / 滑块 | 读 DOM 或截图发现 `captcha`、`verify`、滑块、「请完成安全验证」等 |
| 出现登录墙 / 会话失效 | 页面跳转登录页，或原有元素消失并出现「请登录」 |
| 出现短信/扫码验证 | 任何要求手机验证码、扫码、OTP 的界面 |
| 页面结构与预期不符 | 找不到预期元素（连 `dom_cua_get_visible_dom` 也取不到）、文案与上一轮不一致、表单字段数量变化 |
| 要求上传证件/身份证/银行卡 | 一律停，这类材料不由本 Skill 上传 |
| 要求填写与档案冲突的信息 | 页面要求的字段值在档案中为 `pending` 或不存在 |
| 任何支付、押金、培训费页面 | 一律停，并提示用户警惕招聘收费 |
| 连续 2 次操作无预期变化 | 视为页面异常，不再重试第 3 次 |

**禁止自动重试**：不得为绕过上述任一条件而重复尝试（换选择器、刷新、换浏览器、降级到坐标点击）。一次触发即停。

## 5. 与白名单的关系

- `config/settings.json` 的 `trusted_sources` 是**来源类型**白名单（企业官网 / 官方招聘平台 / 内推 / 手工导入），不是域名白名单。
- 实际目标域名必须由用户在本次会话中逐次给出；不得因为「上次投过这个平台」就默认本次允许。
- 不在白名单来源内的页面（论坛转载、未经验证的第三方聚合站、私信链接）**只做只读分析**，不做任何 L2/L3 操作。

## 6. 截图与 DOM 落盘（隐私）

截图和 DOM 快照是**含个人信息的载体**（页面常带手机号、身份证号、邮箱、住址、薪资期望）。

| 规则 | 做法 |
| --- | --- |
| 位置 | 只允许存 `logs/screens/`（已被 `.gitignore` 排除）；**禁止**存入 `resumes/`、`reports/`、`jobs/raw/`、`docs/` |
| 命名 | `logs/screens/<UTC时间戳>-<job_id>-<用途>.png`，用途取值 `read` / `filled` / `submit-result` |
| 生命周期 | 提交结果截图保留作为证据引用；其余中间态截图在本次运行结束时删除 |
| 引用方式 | 报告中只写文件名与用途，**不把截图内容转成文本写进报告**（避免手机号等进入可提交的报告） |
| 禁止 | 不上传截图到任何第三方；不把 DOM 全文粘进报告或提交材料 |

## 7. 能力状态联动

- `browser_exec` 在 `config/settings.json` 中为 `unverified` 时，本文件全部条款**不生效**（因为无法执行），此时走 `5.3 未接入时的降级输出（人工操作清单）`。
- 变 `verified` 的唯一条件：**用户实测完成一次「A 路径只读」**——即 `user_open_tabs` → `tabs_claim` → `dom_cua_get_visible_dom` 成功取到目标页结构，并把证据登记到 `config/settings.json` 的 `evidence` 字段。
- 只读验证通过 ≠ 允许 L3。L3 需要单独的一次实操确认，且确认记录写入 `logs/`。

## 8. 快速自检（每次浏览器操作前）

- [ ] 走的是 A 路径（用户已登录标签页），还是 B 路径（公开页只读）？有没有不小心走到 C？
- [ ] 接管前是否向用户复述了标签标题与 URL 并得到确认？
- [ ] 本轮操作属于 L0 / L1 / L2 / L3 哪一层？该层要求的确认拿到了吗？
- [ ] 能读 DOM 却用了坐标点击吗？（是 → 改用 `dom_cua_*`）
- [ ] 提交是否被单独确认过？是否只点了一次？
- [ ] 截图存到 `logs/screens/` 了吗？有没有混进 `reports/`？
- [ ] 出现验证码/登录墙/结构变化时，是否会立即停而不是重试？
