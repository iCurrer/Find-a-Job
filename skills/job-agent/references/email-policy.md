# 邮件沟通规范（email-policy）

> 适用：任何以用户本人身份向 HR / 招聘方 / 内推人发出的邮件。
> 定版：2026-10-29 ｜ 对应 `config/settings.json` 的 `email_exec` 能力项与 `executor_policy.email`。

## 0. 先分清两个邮箱

| | 用户求职邮箱（本文件管的） | 智能体邮箱（**不是**这个用途） |
| --- | --- | --- |
| 连接器 | **QQ 邮箱 `qq-mail`**（或其他用户本人的邮箱连接器） | `agent-mail` |
| 发件人身份 | 用户本人，HR 看到的发件地址是用户的 | 智能体自己，发出去对方看到的是代理地址 |
| 用途 | 投递、跟进、感谢信、补充材料 | 系统通知、自用流转 |
| 本 Skill 是否使用 | **是** | **否** |

> 求职邮件必须用**用户本人邮箱**发出，否则 HR 无法联系、也无法归档。
> 不得用 `agent-mail` 代替，也不得把用户简历转发到 `agent-mail` 再发出去。

## 1. 连接器检查（每次发信前第一件事）

```
1. 检查 qq-mail 连接器是否已连接（是否出现在可用连接器列表中且状态为 connected）
2. 未连接 → 停止，提示用户：「需要你打开 QQ 邮箱连接器，否则我无法用你的邮箱发信」
   —— 给出在哪里打开（对话输入框左下角的连接器菜单），并说明打开后我会继续
3. 不得自行安装、不得改用其他邮箱、不得让用户把密码贴进对话
4. 已连接 → 进入第 2 节起草
```

**硬约束**

- `email_exec` 在 `config/settings.json` 中为 `unverified` 时，一律走 `5.3 降级输出`：把主题、正文、收件人交给用户，由用户自己复制发送。
- 连接器断开 / 授权失效 → 视为未连接，不重试第三次，直接转人工。

## 2. 发送流程（六步，缺一步不发）

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| ① 起草 | 按第 4 节模板写主题与正文，只用 `confirmed` 事实 | `resumes/{job_id}/email-{job_id}-{type}-v{major}.{minor}.md` |
| ② 自检 | 过第 5 节核对表 | 勾完的核对表写进该草稿文件末尾 |
| ③ 展示 | 把**收件人、抄送、主题、正文全文、附件文件名与版本**一次性完整呈现给用户 | 对话里可见的完整内容 |
| ④ 确认 | 得到**一次明确的发送许可**（「发吧」「可以发送」）。沉默、含糊、只回「嗯」都不算 | 确认记录写入 `logs/` |
| ⑤ 发送 | 调用连接器发送 | 发送结果 |
| ⑥ 记录 | 把 `message_id`、发送时间、收件人写回 `applications.json` 的 `notes` 与审计日志 | `submission_evidence` 或跟进记录 |

**关键约束**

- **③ 必须展示全文**。不得说「邮件已写好，直接发吗？」——用户没看到内容就不能算确认。
- **④ 一次确认只对一封信有效**。改一个字都要重新确认。
- **禁止批量发**：不得「这几个岗位都发同一封」。每封的收件人、岗位名、正文里的公司名和职位名必须逐一对应。
- 发送后把实际发出的正文存档，不覆盖草稿历史版本。

## 3. 什么情况发、什么情况不发

| 场景 | 发不发 | 说明 |
| --- | --- | --- |
| 岗位只留了邮箱、官网无投递入口 | ✅ 发 | 走第 4.1 节模板 |
| 官方要求「简历发送至 xxx@xx.com」 | ✅ 发 | 严格按 JD 要求的格式与命名 |
| 投递后 5–7 个工作日无回应，JD 或官网允许跟进 | ⚠️ 可发一次 | 走 4.2 节模板，**同一岗位只发一次** |
| 面试结束后 24 小时内致谢 | ✅ 发 | 走 4.3 节模板 |
| 对方明确说「不要电话/邮件询问进度」 | ❌ 不发 | 尊重明文要求 |
| 同一岗位已跟进过一次，仍无回应 | ❌ 不发 | 再催会损害印象，改为记录 `已过期` 或 `需人工介入` |
| 想把简历群发给多家公司 | ❌ 不发 | 违反第 2 节禁止批量约束 |
| 需要附身份证、银行卡、押金、培训费相关内容 | ❌ 不发 | 招聘收费与索要证件一律视为风险，停止并提示用户 |

## 4. 模板（中文求职邮件，正文控制在 200 字内）

### 4.1 投递邮件

```
主题：应聘{岗位名称}-{姓名}-{最高学历/年级}
例：应聘财务数字化实施顾问-张某-会计学本科2027届

正文：
{称呼，如"HR 老师"：

您好！

我在{来源，如"贵司官网/某平台"}看到「{岗位名称}」的招聘信息，现应聘该岗位。

{一段话，2–3 句：与岗位最相关的 confirmed 事实。必须能对应到档案里的具体条目，
不要写"学习能力强""有责任心"这类无法验证的评价。}

简历见附件（{文件名}）。期待有机会进一步沟通，谢谢！

{姓名}
{手机号}｜{邮箱}
}
```

**主题行的硬要求**

- 必须含岗位名称、姓名、学历/年级——HR 靠这三项做初筛。
- 岗位名称用 JD 原文写法，不改写、不简写。
- 不含表情、不含「求职」「求收留」等口语化表述。

### 4.2 跟进邮件（同一岗位仅一次）

```
主题：关于「{岗位名称}」应聘进展的咨询-{姓名}

正文：
{称呼}：

您好！

我于{投递日期}投递了「{岗位名称}」岗位（{如已知：简历编号/平台申请号}），目前尚未收到进展通知，
想礼貌确认一下流程是否还在推进中。

如需要我补充任何材料，请随时告知。感谢您的时间！

{姓名}
{手机号}
```

### 4.3 面试后致谢（24 小时内）

```
主题：感谢面试机会-{岗位名称}-{姓名}

正文：
{称呼}：

您好！

感谢您{日期}的面谈时间。通过交流，我对「{岗位名称}」的{某个具体职责/业务方向}有了更具体的了解，
也更确认自己的{某项 confirmed 经历}与该岗位的契合。

如需补充材料，我很乐意提供。再次感谢！

{姓名}
{手机号}
```

## 5. 发送前核对表（逐项打勾，写进草稿文件）

- [ ] 收件人地址逐字符核对过（尤其 `qq.com` / `qq.con`、`gmail.com` / `gmial.com`）
- [ ] 岗位名称与 JD 原文一致，公司名没有张冠李戴
- [ ] 正文里提到的每一项经历/数字，都能在 `profile.json` 里找到对应 `confirmed` 条目
- [ ] 没有出现 `〔待确认：xxx〕` 占位符（有 → 先补事实，不要发）
- [ ] 附件是**当前版本**的简历，文件名含岗位标识，且与实际内容一致
- [ ] 附件版本号已回填 `applications.json` 的 `resume_version`
- [ ] 称呼正确（知道姓名用「X 老师」，不知道用「HR 老师」，不用「亲」「尊敬的领导」）
- [ ] 正文无错别字、无占位模板残留、无上一封邮件留下的公司名
- [ ] 主题行符合第 4 节要求
- [ ] 已把全文完整展示给用户，并得到一次明确发送许可

## 6. 发送失败的处理

| 情况 | 处理 |
| --- | --- |
| 连接器未授权 / 令牌过期 | 停止，提示用户重新连接 QQ 邮箱；不重试第三次 |
| 收件地址不存在（退信） | 记录退信，回查 JD 原文是否抄错，不改用猜测的地址重发 |
| 发送成功但对方未回 | 不自动催；到跟进时间点（5–7 工作日）由用户决定是否发 4.2 |
| 部分字段编码异常（乱码） | 停止，检查连接器编码设置，不带乱码硬发 |
| 重复发送风险（同一岗位已发过） | 拒绝发送，提示已有记录与发送时间 |

## 7. 落盘与隐私

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 邮件草稿 | `resumes/{job_id}/email-{job_id}-{type}-v{major}.{minor}.md` | 与简历定制版同目录，便于一起归档 |
| 发送记录 | `applications/applications.json` 的 `notes` + `logs/*.jsonl` | 含 `message_id`、时间、收件人 |
| 附件 | `resumes/{job_id}/` 下的导出文件 | PDF/DOCX 已被 `.gitignore` 排除 |
| 禁止 | 把邮箱密码、授权码、Cookie 写进任何文件或对话 | 全部由连接器托管 |

## 8. 快速自检（每次发信前）

- [ ] 用的是用户本人邮箱连接器（`qq-mail`），不是 `agent-mail`？
- [ ] 连接器状态是已连接？没连接是否已提示用户去打开，而不是自己想办法绕？
- [ ] 这是第几封给这家公司的信？同一岗位是否已跟进过？
- [ ] 正文每一个事实都能在档案里找到对应的 `confirmed` 条目？
- [ ] 附件是当前版本，版本号准备回填？
- [ ] 全文给用户看过，且拿到了明确的一次许可？
- [ ] 收件地址逐字符核对过？
