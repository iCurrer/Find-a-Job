# 简历与申请材料生成规范（resume-policy）

## 适用范围

- 本文件约束所有**对外材料**：简历（主简历与岗位定制版）、求职信、网申答案、邮件正文、面试自述稿。
- 在以下时机加载：生成、修改、导出一份对外材料之前；核对材料事实之前；登记材料版本之前。
- 原则：**只有 `confirmed` 事实可以写入对外材料**；材料不得新增未经用户确认的经历、证书、数字、技能或时间。

## 1. 材料范围与存放位置

所有材料存放在 `resumes/`，**只新增版本，不覆盖历史版本**：

| 类型 | 路径与命名 | 说明 |
| --- | --- | --- |
| 主简历 | `resumes/main-resume-v{major}.{minor}.md` | 由已确认档案整理，作为所有定制版的基准 |
| 岗位定制版 | `resumes/{job_id}/resume-{job_id}-v{major}.{minor}.md` | 针对单个岗位调整排序与表达 |
| 求职信 | `resumes/{job_id}/cover-letter-{job_id}-v{major}.{minor}.md` | 按需生成，不强制 |
| 版本说明 | `resumes/{job_id}/VERSION.md` | 记录目标岗位、生成日期、基准主简历版本、变更摘要、待确认项 |
| 导出文件（PDF/DOCX） | 与 Markdown 源文件同目录同名 | 导出是派生文件，源文件始终保留 |

版本号规则：

- 格式 `v{major}.{minor}`，例如 `v1.0`、`v1.1`、`v2.0`。
- **主简历**：`major` 在已确认事实变化（新增实习、学历更新、证书取得）时 +1，并重置 `minor=0`；仅措辞/排版调整时 `minor` +1。
- **岗位定制版**：首次生成为 `v1.0`；每次基于同一岗位重新生成，`minor` +1；目标岗位或基准主简历版本变化时 `major` +1。
- 版本标识必须可回填到申请记录：`resume_version` 写完整标识，例如 `resume-job-6d4169afd8-bb41-v1.0`；`cover_letter_version` 写 `cover-letter-job-6d4169afd8-bb41-v1.0`。
- 同一版本号不得对应两份不同内容；发现重名冲突时停止生成并报告。

## 2. 事实使用规则

### 2.1 允许的行为

- 从 `confirmed` 经历中选择与岗位最相关的条目，调整顺序与篇幅。
- 使用岗位描述中的术语改写**已有事实**的表达方式（同义改写，不改变含义）。
- 按岗位关键词调整措辞与加粗重点，但每条描述仍可追溯到档案。
- 省略与岗位无关的 `confirmed` 经历（省略不是编造）。

### 2.2 禁止的行为

- 编造或夸大学历、毕业时间、证书、实习、项目、获奖、技能熟练度。
- 把「备考中/未通过/计划中」写成「已取得/持有」。
- 把岗位描述原文直接复制成个人经历（JD 冒充经历）。
- 编造业绩数字、用户量、增长率、排名、耗时；不得用估算值冒充事实。
- 把 `pending` 或 `expired` 事实写成确定事实。
- 把他人经历、团队成果全部归为个人成果（团队成果需注明角色）。

### 2.3 缺失数字与缺失信息

- 档案缺少数字时，在材料中使用统一占位：**`〔待确认：<字段>〕`**，例如「〔待确认：接口 QPS〕」「〔待确认：实习起止时间〕」。
- 占位不得被删除后填成猜测值；导出前若仍未确认，保留占位并在报告中列为待确认项。
- 缺失技能/证书时，不写入该条；在求职信或报告中说明「如需补充请确认」，不虚构。

## 3. 生成流程

1. **前置检查**：档案已通过 `validate_profile.py`；目标岗位已有 `job_id` 与评分结果；用户已选定该岗位。
2. **素材选择**：按 `references/job-scoring.md` 的职责匹配理由，挑选相关经历与技能；每条素材记录来源 `fact_id` / 档案路径。
3. **起草**：生成 Markdown 草稿，头部写元信息（`job_id`、公司、岗位、版本、日期、基准主简历版本、待确认项）。
4. **事实核对**：逐条比对草稿与档案，形成核对表（见第 4 节）；发现无来源内容立即删除。
5. **用户审核**：展示草稿与待确认项，等待用户确认；确认前材料不得外发。
6. **导出**：仅在用户要求时导出 PDF/DOCX；导出前完成第 6 节检查。
7. **记录版本**：写入 `VERSION.md`；投递时把版本标识填入 `applications.json` 对应字段。

## 4. 材料事实核对表

每份材料生成后附带核对表（可放在 `VERSION.md` 或独立报告），确保每条内容可追溯：

```json
{
  "resume_version": "resume-job-6d4169afd8-bb41-v1.0",
  "job_id": "job-6d4169afd8-bb41",
  "base_main_resume": "main-resume-v1.0",
  "generated_at": "2026-10-29T12:30:00+08:00",
  "facts": [
    {"material_text": "示例大学 计算机科学与技术 本科（2023-09 至 2027-06）", "source": "profile.education[0]", "status": "confirmed"},
    {"material_text": "负责示例接口设计与实现", "source": "profile.experience[0].highlights[0]", "status": "confirmed"},
    {"material_text": "〔待确认：接口 QPS〕", "source": "profile.experience[0].highlights[0]", "status": "pending"}
  ],
  "pending_items": ["接口 QPS 待确认"],
  "forbidden_checked": ["无新增数字", "无未确认证书", "无 JD 原文冒充"]
}
```

核对表本身不写入简历正文，只作为可审计记录。

## 5. 示例（占位数据）

生成后的目录形态：

```
resumes/
├── main-resume-v1.0.md
└── job-6d4169afd8-bb41/
    ├── resume-job-6d4169afd8-bb41-v1.0.md
    ├── cover-letter-job-6d4169afd8-bb41-v1.0.md
    └── VERSION.md
```

`VERSION.md` 示例：

```markdown
# 版本说明 — job-6d4169afd8-bb41

- 目标岗位：示例科技 / 后端开发实习生
- 生成日期：2026-10-29T12:30:00+08:00
- 基准主简历：main-resume-v1.0
- 本次变更：突出接口开发与 Python 经历；弱化无关课程项目
- 待确认项：接口 QPS；实习起止时间
- 事实来源：profile.education[0]、profile.experience[0]、profile.skills[0]
```

申请记录中的版本回填示例：

```json
{
  "application_id": "app-20261029-0001",
  "job_id": "job-6d4169afd8-bb41",
  "resume_version": "resume-job-6d4169afd8-bb41-v1.0",
  "cover_letter_version": "cover-letter-job-6d4169afd8-bb41-v1.0",
  "status": "待确认"
}
```

## 6. 导出前检查清单

- [ ] 所有事实条目均有核对表来源，且状态为 `confirmed`（占位项除外）。
- [ ] 无编造数字、证书、时间、技能；无「待确认」被误删。
- [ ] 岗位名称、公司名称与 `jobs/*.json` 一致，无错别字。
- [ ] 联系方式与档案 `basics` 一致（示例/文档中保持脱敏）。
- [ ] 文件命名符合第 1 节规范，版本号未复用。
- [ ] PDF/DOCX 导出后抽查版式：分页、字体、表格、链接可读。
- [ ] 材料头部元信息（版本、目标岗位、日期）与实际一致。

## 7. 失败处理

| 情形 | 处理 |
| --- | --- |
| 缺少可写入的事实（无相关 `confirmed` 经历） | 不生成该条内容；报告中说明「证据不足」，建议补充档案或用其他经历 |
| 用户要求写入未确认事实 | 拒绝写入；提供「先补档确认」或「标注待确认」两种合规选项 |
| 用户要求编造数字/证书 | 拒绝，并说明诚信与背调风险；给出去掉该条或标注待确认的替代方案 |
| 版本号冲突/文件已存在 | 停止生成，展示现有版本与冲突文件；按第 1 节规则递增版本，不覆盖 |
| 导出工具不可用（PDF/DOCX 失败） | 保留 Markdown 源文件并告知用户；不算生成失败，报告中注明「未导出」 |
| 事实核对不通过 | 删除无来源内容后重新核对；仍不通过则停止并要求用户补充 |
| 用户未确认即要求外发 | 拒绝；补充确认点，等待显式批准 |
