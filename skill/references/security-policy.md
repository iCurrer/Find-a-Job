# 安全、隐私与平台边界规范（security-policy）

## 适用范围

- 本文件约束本 Skill 的数据处理、凭据管理、权限、外部写入授权、平台合规与日志记录。
- 在以下时机加载：任何涉及敏感信息的操作之前；任何外部写入（投递、发邮件、上传资料、提交声明）之前；配置日志与备份之前；发现异常或安全事件时。
- 总原则：**本地优先、凭据隔离、最小权限、明确授权、遵守平台规则、日志不记敏感信息**。

## 1. 本地优先

1. 个人档案、简历、岗位数据、申请记录默认保存在用户可控的工作区 `JobAgent/` 内。
2. 默认不上传个人资料到第三方服务器、云盘或在线表单聚合服务。
3. 如确需远程访问或备份，必须由用户明确指定目标与范围，并采用认证、加密与最小权限；未确认前视为禁止。
4. 服务器、定时任务、移动端接入都不是 MVP 前置条件；未验证前不启用。
5. 文档、示例与测试数据一律使用占位人物（如「示例同学」）与脱敏联系方式。

## 2. 凭据隔离

1. 密码、Cookie、令牌、验证码、登录态**不得**出现在：Skill 文档、`references/`、`config/*.json`、`profile/`、`jobs/`、`applications/`、`resumes/`、`reports/`、`logs/`、版本控制。
2. 脚本不接收、不存储、不打印凭据；执行器如必须登录，由用户在受控会话中自行完成，本 Skill 不代填、不读取。
3. 示例与模板中的凭据字段只能写占位符：`<由用户本人在执行器中提供>`。
4. 发现凭据落入文件：立即停止相关流程 → 记录事件（不含凭据内容）→ 协助用户删除并轮换 → 检查备份与历史记录。
5. 不把 `applications.json.bak`、日志、截图中的敏感内容外发；截图由用户自行管理。

## 3. 最小权限

1. 执行器只获得当前任务所需的最小权限：单平台、单岗位、单次动作。
2. 不申请「长期免确认」「批量投递」「全盘读写」类权限。
3. 浏览器/手机工具在 P0 未取得验证证据前视为「未接入」，不调用、不假设可用。
4. 用户可随时要求停止；停止后不重试、不排队执行剩余动作。
5. 脚本只读写项目内约定路径，不访问用户其他目录。

## 4. 明确授权

外部写入分级：

| 操作 | 授权要求 |
| --- | --- |
| 读取项目内文件、运行本地脚本、生成评分与草稿 | 只读/本地写入范围内可执行 |
| 写入 `reports/`、`resumes/`、`jobs/` 新文件 | 属本地过程产物，可执行，但报告需说明 |
| 更新 `applications.json` 状态 | 按状态机与确认点执行；`已提交` 需证据 |
| 真实投递、上传个人资料、发送邮件、提交声明 | **必须逐项显式确认**，一次授权只对应一次动作 |
| 修改 `profile.json`、删除记录、覆盖材料 | 必须用户明确同意 |

确认请求模板：

```markdown
### 待确认操作（请回复「确认提交」或「取消」）

- 平台/页面：示例招聘平台（来源链接在记录中）
- 公司/岗位：示例科技 / 后端开发实习生
- 目标 job_id：job-6d4169afd8-bb41
- 材料版本：resume-job-6d4169afd8-bb41-v1.0 / cover-letter-job-6d4169afd8-bb41-v1.0
- 将要执行：上传 2 份材料并点击提交
- 提交后动作：登记证据并更新状态为「已提交」
- 预计影响：向该平台提交一次真实申请

（未收到明确确认前，不执行任何外部写入。）
```

- 含糊表述（「可以吧」「试试」）不构成授权；需明确的肯定指令。
- 授权不跨岗位、不跨平台、不跨时间复用。

## 5. 平台规则

1. 只使用平台允许的功能与访问方式；遵守目标网站/App 的服务条款与 robots 等约定。
2. 遇到验证码、登录保护、风控提示或明确禁止自动化的条款：立即停止相关自动操作，转 `需人工介入`，不尝试绕过。
3. 不进行高频批量请求、不模拟多账号、不伪造设备指纹。
4. 招聘信息只从公开可访问、且允许相应访问方式的页面获取；无法确认授权来源时只做人工导入。
5. 平台页面结构变化导致操作失败时停止，不猜测元素位置、不硬编码注入。

## 6. 个人信息保护

1. 收集范围遵循最小必要：只收集求职直接需要的字段，不收集身份证号、银行卡、精确住址、家庭成员信息。
2. `profile_id` 等本地标识不得包含身份证号、手机号等敏感标识。
3. 上传个人资料到第三方（招聘平台、背调、邮件）前，向用户说明用途、范围与去向，并取得对应授权。
4. 报告中展示个人信息时做必要脱敏（示例：`138****0000`、`example@example.com`）。
5. 不将档案或申请记录用于求职以外的目的；不共享给无关第三方。

## 7. 日志与审计记录

允许记录（JSONL，一行一条）：

```json
{"at": "2026-10-29T12:30:00+08:00", "task": "update_application", "application_id": "app-20261029-0001", "job_id": "job-6d4169afd8-bb41", "from": "待确认", "to": "执行中", "result": "ok", "note": "用户已确认"}
```

字段白名单：`at`、`task`、`skill_version`、`script_version`、`application_id`、`job_id`、`from`、`to`、`result`、`exit_code`、`note`（摘要）。

禁止记录：密码、Cookie、令牌、验证码、身份证号、银行卡号、完整住址、完整手机号、邮箱正文、平台账号密码、截图中可识别的敏感信息。

规则：

1. 日志只记时间、任务、目标岗位、步骤摘要、结果与错误，不记录不必要的个人信息。
2. `note` 字段为人工摘要，写入前检查是否含敏感内容。
3. 日志与 `.bak` 属于本地审计材料，不随报告外发；如需提供给他人，先脱敏。
4. 审计日志只追加，不改写历史。

## 8. 备份与恢复

1. 状态更新前自动生成 `applications.json.bak`；重要变更前建议整体备份 `JobAgent/` 数据目录。
2. 主简历与岗位定制版分开存放，避免误覆盖；材料版本只增不删。
3. 恢复流程：停止写入 → 对比差异 → 用户确认 → 用备份恢复 → 记录恢复原因与时间。
4. 备份文件同样遵守本地优先与凭据隔离要求。

## 9. 安全事件与失败处理

| 事件/失败 | 处理 |
| --- | --- |
| 发现凭据写入文件/日志 | 停止流程；删除并轮换凭据；记录事件摘要（不含凭据）；检查备份与历史 |
| 用户明确禁止的操作被请求（如绕过验证码） | 拒绝并说明原因；提供人工操作或合规替代方案 |
| 未授权外发个人信息 | 操作被阻止并请求明确授权；留存请求记录 |
| 平台风控/账号受限 | 立即停止自动操作，交由用户处理；不尝试规避 |
| 文件被非预期修改/覆盖 | 停止写入；用 `.bak` 或历史版本恢复；报告差异与原因 |
| 目标页面与预期不符 | 不继续填写/提交；转 `需人工介入`，请用户核对 |
| 未能取得用户明确授权 | 不执行外部写入，输出待确认清单（见第 4 节模板） |
| 日志写入失败 | 保留 stdout 输出与错误信息，报告路径问题；不因此跳过安全校验 |
| 备份文件缺失或损坏 | 停止写入；请用户从其他副本恢复；无法恢复时保留当前状态并报告差异 |
| 脚本退出码 `1`（规则失败） | 报告具体规则与受影响记录，修复后重跑；不绕过规则 |
| 脚本退出码 `2`（参数/文件缺失） | 核对路径与参数，输出修正后的完整命令；不生成占位数据 |

## 10. 验收检查清单

- [ ] 文档、配置、日志、示例中无真实密码/Cookie/令牌/身份证号。
- [ ] 所有外部写入均有显式确认记录，且一次授权对应一次动作。
- [ ] 执行器权限为最小集合，可随时停止。
- [ ] 平台规则已确认，遇验证码/风控即停止。
- [ ] 日志字段符合白名单，不含敏感信息。
- [ ] 状态更新前有 `.bak`，材料主版本与定制版本分开。
- [ ] 报告中个人信息已脱敏，未上传未授权数据。
